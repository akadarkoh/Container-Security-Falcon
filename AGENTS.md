This is a spec that you should use to implement a project that builds a container image from source and deploys it.

**Required Services**

-   **GitHub**: Source code repository.
-   **Amazon ECR**: Stores the built container images.
-   **AWS CodePipeline**: Orchestrates the build and deploy workflow.
-   **AWS CodeBuild**: Builds the Docker image from source, scans it, and pushes it to ECR.
-   **Amazon S3**: Artifact store for CodePipeline.
-   **AWS IAM**: Roles for CodePipeline and CodeBuild.
-   **CloudWatch Logs**: Stores build and pipeline logs.
-   **Optional**: AWS KMS (for artifact encryption), AWS CodeDeploy (for blue/green ECS deployments), Amazon ECS/EKS (as a deployment target), SNS/Chatbot (for notifications).

**Implementation Steps**

-   **Create ECR repo**: To store the Docker images built by the pipeline.
-   **Create S3 artifact bucket**: For CodePipeline artifacts.
-   **Create CodeBuild project**:
    -   Environment: Use a managed image with Docker support and enable "Privileged" mode for the Docker daemon.
    -   Service role: Grant permissions for ECR login, pushing images (`ecr:PutImage`, etc.), S3 artifact access, and CloudWatch Logs.
-   **Create CodePipeline**:
    -   **Source action**: Provider "GitHub". Connect to your repository and branch.
    -   **Build action**: Your CodeBuild project, which consumes the source artifact from the GitHub trigger.
    -   **Deploy stage**: An ECS/CodeDeploy action that uses the `imagedefinitions.json` file generated by the build stage.
-   **Grant IAM**:
    -   **CodePipeline role**: Needs access to the S3 artifact bucket, permission to invoke CodeBuild, and access to the source repository (e.g., via AWS Connector for GitHub or a token in Secrets Manager).
    -   **CodeBuild role**: Needs ECR read/write permissions, S3 artifact read/write, and CloudWatch Logs write access.

**Sample buildspec (build, scan, push)**

-   File: `buildspec.yml` for the CodeBuild action.
-   What it does: Checks out the source code, logs into ECR, builds the Docker image, runs a security scan with Trivy, and pushes the tagged image to ECR. It then creates an `imagedefinitions.json` file for the deployment stage.

```yaml
version: 0.2

phases:
  pre_build:
    commands:
      - echo "Logging into Amazon ECR..."
      - aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com
      - REPOSITORY_URI=$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$IMAGE_REPO_NAME
      - IMAGE_TAG=$(echo $CODEBUILD_RESOLVED_SOURCE_VERSION | cut -c 1-7)
  build:
    commands:
      - echo "Building Docker image..."
      - docker build -t $REPOSITORY_URI:$IMAGE_TAG .
      - echo "Running Trivy scan..."
      - trivy image --exit-code 0 --format json -o trivy.json $REPOSITORY_URI:$IMAGE_TAG
  post_build:
    commands:
      - echo "Pushing Docker image to ECR..."
      - docker push $REPOSITORY_URI:$IMAGE_TAG
      - echo "Creating imagedefinitions.json for deployment..."
      - printf '[{"name":"falcon-app","imageUri":"%s"}]' $REPOSITORY_URI:$IMAGE_TAG > imagedefinitions.json

artifacts:
  files:
    - imagedefinitions.json
    - trivy.json
```

**Deploy Options**

-   **ECS Standard**: Add a CodePipeline “ECS deploy” action targeting a service/task definition. It will use the `imagedefinitions.json` artifact to deploy the new image.
-   **ECS Blue/Green**: Use CodeDeploy with the ECS provider for advanced features like traffic shifting and health checks.
-   **EKS**: Add a CodeBuild action that runs `kubectl set image ...` or `helm upgrade ...`.

**IAM Policy Tips**

-   **CodeBuild role needs**:
    -   `ecr:GetAuthorizationToken`
    -   `ecr:BatchCheckLayerAvailability`, `ecr:InitiateLayerUpload`, `ecr:UploadLayerPart`, `ecr:CompleteLayerUpload`, `ecr:PutImage`
    -   `logs:CreateLogGroup`, `logs:CreateLogStream`, `logs:PutLogEvents`
    -   `s3:GetObject`, `s3:PutObject` on the artifact bucket.
-   **CodePipeline role needs**:
    -   `codebuild:StartBuild`, `codebuild:BatchGetBuilds`
    -   `s3:GetObject`, `s3:PutObject` for the artifact bucket.
    -   `iam:PassRole` for the roles passed to other services (like ECS).
    -   Permissions for the chosen deploy action (e.g., `ecs:UpdateService`).

**Local Development**

While the pipeline automates the build and push process, you may want to build and test images locally. Use the following steps to authenticate and push an image to your repository.

1.  **Authenticate Docker to ECR:**
    ```bash
    aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 449095351082.dkr.ecr.us-east-1.amazonaws.com
    ```
2.  **Build your Docker image:**
    ```bash
    docker build -t box-office-repo .
    ```
3.  **Tag the image for your ECR repository:**
    ```bash
    docker tag box-office-repo:latest 449095351082.dkr.ecr.us-east-1.amazonaws.com/box-office-repo:latest
    ```
4.  **Push the image to ECR:**
    ```bash
    docker push 449095351082.dkr.ecr.us-east-1.amazonaws.com/box-office-repo:latest
    ```
